01 · Why Jarvis exists

The device you speak to should not have to be the device that does the work. Jarvis understands the request, picks the permitted device, explains what it plans to do, does only what is allowed — and says so plainly when something is not built yet.

26

Tools in the registry — files, reminders, memory, search, browser, device status and read-only Google

181

Tests in the suite — 159 passed, 22 skipped on platforms they do not apply to

4

Steps in every task — understand, choose a permitted device, act, report back

5

Apps on the launch allowlist — Notepad, Calculator, Paint, File Explorer and Command Prompt

Every number above is counted from the code in the Jarvis repository — the tool registry, the test suite, the four-step flow and the app allowlist.

02 · How it works

What happens after you press enter.

01

Understand the request

Jarvis reads what you asked — typed or spoken — and works out what you want and which device it belongs to. If the request is unclear, it asks instead of guessing.

Check Is the target clear? If not, ask — never guess.

02

Choose a permitted action

It checks the request against the allowlist and your permissions. An action that is not permitted is never run silently.

Check Allowed and confirmed? If not, say so.

03

Perform supported actions

Only approved actions run, and anything that changes something asks for your confirmation first. You can stop a running task at any time.

Retry A failed step goes back one step — or stops and reports.

04

Show the result

The result comes back to the device you asked from, with a short record of what was done in the activity history.

Check Result reported, action logged. Nothing hidden.

06 · Safety

Built to say when it can’t — and to prove what it did.

Your privacy is the boundary. Everything Jarvis can do is gated by an allowlist, a confirmation, or a permission — and everything it does is written to a log you can read.

43 / 52

Endpoints behind a session

43 of the backend’s 52 API routes require authentication or an active user session. Zero unauthenticated write access.

128-bit

Confirmation IDs

Every state-changing action creates a one-time confirmation ID from 16 random bytes — 128 bits — that you approve or deny.

5

Apps on the launch allowlist

Only Notepad, Calculator, Paint, File Explorer and Command Prompt can be launched. Anything else is safely refused.

26 / 26

Tools write to the audit log

All 26 tools run through the registry, which records every call — success or failure — with secrets and file contents redacted.

Cloud-first isolation

The Jarvis cloud backend authenticates via Google OAuth and encrypts user BYOK keys. There is no unauthenticated telemetry or background sync.

Permissions first

Apps can only be launched from an allowlist, files only inside approved folders, and browser actions only on domains you approve. Sensitive fields — passwords, cards, tokens — are never read or filled.

What leaves your device

Chat text and the content you ask to summarise are sent to Gemini using your own API key; search queries go to your chosen search provider. Passwords and API keys are never stored in memory or logs.
